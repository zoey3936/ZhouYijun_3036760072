# AI-Use Disclosure

## Where and how AI was used
I used one AI assistant (Kimi) throughout this project. It produced the first drafts of all five Python scripts (data loading, the DiD regression, the figure, the robustness checks, and the extension), which I ran on my own machine in VS Code and checked line by line. It also helped me learn to read regression output by explaining the coefficient table, standard errors, and p-values, and how the manual DiD calculation relates to the regression version. Finally, it suggested the structure of this report and produced an English draft of each section, which I revised sentence by sentence and partly rewrote; the limitations section, for example, reflects my own judgment about which caveats matter most.

## How AI-generated code, analysis, and writing were checked
Every number in this report comes from code I executed myself, and the key results were checked in several independent ways. I computed the DiD estimate by hand from group means before running any regression (2.718); the regression coefficient came out at 2.7179, and matching the two confirmed that I understood what the interaction term estimates. Every replicated quantity was then compared with the original paper: my baseline estimate of 2.72 against their 2.75 (Table 3), my wage DiD of 0.48 against their roughly 0.47, and the store counts in my Table 2 against their sample description. I verified the FTE formula (full-time + managers + 0.5 times part-time) against the paper's definition before using it, and checked the extension's group sizes (277 low-wage vs. 44 high-wage stores) by tabulating the data directly. In the extension, I also confirmed the first stage before interpreting the second: the wage regression must show the policy raised wages before any employment effect can be attributed to it.

## Important AI errors or suggestions that were corrected or rejected
A few AI errors or suggestions were corrected or rejected along the way. Kimi's first scripts assumed the data lived in a folder path that did not match my machine, and the script crashed with a file-not-found error; I diagnosed the path by comparing the code against the actual folder layout and fixed it myself. The first code draft also kept only stores with completed follow-up interviews without discussing why stores were missing; I checked the status variable and found that stores differed in their reasons (permanent closure vs. refusal vs. renovation), and I decided to keep the 399 completed interviews as the main sample while discussing the six closures as a limitation, rather than silently letting the code decide. Finally, early drafts of this report described the baseline estimate as confirming the paper's result. I rejected that framing, since the estimate is significant only at the 10% level, and the report now states this openly and discusses why the fuzziness fueled the subsequent debate.

I take responsibility for every data choice, line of code, table, and conclusion in this project.
